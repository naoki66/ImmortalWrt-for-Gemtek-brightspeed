# B26 聚合状态修正与 2.4GHz 排查说明

基线：`8004ae29ebae2268168f74cc472ee7c9156928f2`（B26）。本轮不修改 YYH、不恢复已取消的 B27 TCP 反馈服务。

## 实际修正

- `mt7996_ampdu_action()` 的 RX_START 检查 `mt76_rx_aggr_start()` 返回值，缓冲分配失败时向 mac80211 返回错误，停止下发硬件 BA 配置。
- RX BA MCU 配置失败时，尝试撤销可能已成功的链路配置，释放本次软件重排状态，保留原始错误码。撤销失败另行限频记录。
- TX_OPERATIONAL 只在 MCU 配置成功后标记 `mtxq->aggr`。失败时在驱动 mutex 解锁后，通过 mac80211 现有异步停止接口终止 BA，避免上层继续保留“已聚合”的虚假会话。
- BA 操作失败加入限频日志，包含操作、站点 MAC、TID 和错误码。

正常成功路径、频段策略、无线 bin、EEPROM、PCIe、NPU、拥塞控制、收发窗口和 DSCP 不变。本补丁适用于相关聚合失败路径，并非只针对 2.4GHz。

## 参考和依据

- OpenWrt mt76 `0936617dc529ff9da0385221d3fa6de732231177`：`mt7996/main.c` 的 `mt7996_ampdu_action()`；`agg-rx.c` 中分配失败返回 `-ENOMEM`，以及 `mt76_rx_aggr_stop()` 的释放流程。
  https://github.com/openwrt/mt76/tree/0936617dc529ff9da0385221d3fa6de732231177
- 当前 B26 实际构建的 `mac80211-regular/backports-7.2/net/mac80211/agg-tx.c`：`ieee80211_agg_tx_operational()` 忽略驱动回调的返回值；`ieee80211_stop_tx_ba_session()` 设置 WANT_STOP 并排入 wiphy work，不同步递归调用驱动。
- 同目录 `agg-rx.c`：RX_START 返回错误时，上层拒绝本次 ADDBA，不应继续保留本次软件重排对象。

这是依据当前调用约定实现的本地错误处理修正，不是从厂商固件复制的性能补丁。

## 验证与边界

直接抽取修改前后完整 `mt7996_ampdu_action()`，在依赖注入测试中检查七种场景：RX 分配失败、RX MCU 失败、TX MCU 失败、RX/TX 成功，以及 RX/TX 停止。修改前前三项失败；修改后七项通过。测试同时检查 TX 停止请求发生在驱动解锁之后。

补丁以 fuzz=0 正向应用及反向还原，并核对完整文件内容。驱动交叉编译结果见本目录构建日志。以上不是实机吞吐验收。

**当前 2.4GHz 双向低速尚未证实由这些失败路径触发，本补丁不能标为已根治。** 之前 B26 的聚合采样显示 TID0 BA 已存在，没有捕获 BA 配置失败。新日志可以检验这个分支，而非预设它成立。

已有证据：退出 HE 改 HT20 后仍下行约 4.5Mbps，故不能将关闭 OFDMA 当作充分修复；NDIS 与 AP 硬件戳的探针对照显示，主要额外等待位于 AP 收包之前，但仍包含终端队列、空口与 AP 互操作，不能只归咎于电脑网卡。

## 实机检验方法

刷入包含本补丁的候选固件后，在相同位置、信道、20MHz 带宽和默认窗口下，做单向上传、单向下载和 P4 双向不限速测试。电脑绑定实际无线 IP，管理与日志采集走有线。测试前后保存 boot_id、dmesg、AP 站点/BA 状态。

重点查找 `BA action ... failed` 和 `RX BA rollback failed`。若低速持续、且未出现这些错误，应继续追查 AP 接收前的排队和空口过程；不能继续将该错误处理修正宣传为低速修复。

回退：使用本目录反向补丁，或切回原 B26 分支 `xr1710g-B26-mtk-amsdu-alignment`。原 B26 提交保留，不自动刷机或修改正在运行的路由器。
