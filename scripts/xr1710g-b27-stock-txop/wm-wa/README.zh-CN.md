# B27：WM/WA 内部调度离线逆向报告

本次已解出量产样本与当前构建的 WM/WA region，并从机器指令还原了 WA 的 ACM 配置状态机、百分比阈值换算，以及 WM 的 VOW 八档量子命令处理。尚未完成全部发包调度、随机丢弃判定、ROM 内部和硬件行为的等价证明。没有操作路由器，没有修改运行中的无线，也没有生成或刷入新固件。

## 1. 对此前判断的纠正

此前状态文档认为“算法区域加密、缺少明文，因此无法继续分析”，这个判断已经过时。本次四个样本均能用 AES-128-CBC、128 位全零 key、128 位全零 IV 解出连贯指令、源码路径和调度日志；每个 region 单独重置 IV。

每个 region 的最后 16 字节是明文尾部，前 12 字节为零，末 4 字节含义尚未确定。正式提取工具只对此前的 payload 解密，避免把尾部误当代码。常规 CRC32 探测未匹配末字，不能称完整性校验或签名验证通过。提取工具会核对输入文件 SHA256 和 trailer/region 元数据。

样本详见 `sample-manifest.json`，不在 Git 中附带整份原厂固件或解密镜像。

## 2. 解码方式及可信边界

CPU 为 RISC-V，使用压缩指令与 Andes 扩展。Capstone 5.0.6 单独使用时会将不认识的 32 位 Andes 指令拆成两个半字，导致错误控制流。本次工具按原始指令长度推进，补齐 GP 相对寻址、GP load/store、常量/位测试分支、位域提取和 LEA，并保留未知指令，不静默跳过。

WA 两版的 GP 均为 `0x10216800`。原厂 WA 静态引用恢复为 669 处、当前为 597 处；选择的 WA 代码 region 中均剩 3 个未解码指令。WM 仍有大量未处理的压缩扩展、代码/数据混合，不把线性扫描结果称为完整函数反编译。普通字符串相同不构成算法相同的证据。

GP 有符号立即数解码与 Andes 官方宏经 C 编译后的结果进行了 30,000 组随机比对，全部一致。范围包括字节/半字/字寻址与存储，不覆盖每一条扩展指令。

## 3. 已还原：WA ACM 配置状态机

原厂入口 `0xe0003a62`，当前入口 `0xe0004120`。两版函数均为 143 条指令；配置分支、状态字段布局、表读取循环一致，差异主要是代码地址、全局地址与下级函数位置。

以下偏移相对于传入 WA 请求指针；不能直接当作 Linux 驱动请求结构起点。原厂内部状态基址为 `GP-70016`，当前为 `GP-70912`，均非可在 Linux 直接访问的地址。

- 请求 `+0x2c` 为操作码；状态 `+0x1d4` 是累积更新标志。
- op=1：更新标志 OR `0x0f`。
- op=2：OR `0x02`，更新 token/阈值配置区域。
- op=3：OR `0x01`，更新四路资源的满载/丢弃百分比表。
- op=4：OR `0x04`，更新尾丢弃表。
- op=5：OR `0x10`，调用 STA 配置子函数。
- op=9：清更新标志，并清状态 `+0x1d0` 的 bit1。
- 其他 op 不新增更新位；原来存在的更新位仍会驱动后面的写入。它不是每条命令先清零的无状态 switch。

按更新位执行：

| 更新位 | 读取请求位置 | 状态写入/动作 |
| --- | --- | --- |
| bit3 | `+0x34/+0x36` 两个 16 位值 | 截断为 8 位保存到 `+0x21a/+0x21b`，分别调用下级 setter |
| bit1 | `+0x38` 四个 u16；`+0x40` 四个 u16 | 保存至 `+0x1f0` 与 `+0x1f8`；`+0x2d` 非零时读取 `+0x2a4..+0x2a7` 四字节掩码 |
| bit0 | `+0x48` 的 4×8 u16；`+0x88` 的 4×8 u16 | 交错保存为每资源 64 字节的 u32 满载/丢弃表，调用四次资源编程函数 |
| bit2 | `+0xc8` 与 `+0xf0` 两组表 | 输入每组跨度为 5 个 u16，但本函数每组只复制前 4 个；第五项的其他用途尚未确认 |
| bit4 | `request+0x34` | 调用 STA 子函数，本轮不以替身结果证明其内部等价 |

168 组离线解释测试覆盖 op 0..10、255，以及初始更新位 0/1/2/4/8/16/31。两版配置函数解释执行后的全部 4096 字节状态区，与独立模型逐字节一致。日志、硬件 setter、表编程与 STA 子调用做了替身处理；不是整颗 WA 的指令模拟。

## 4. 已还原：满载与丢弃百分比转换

原厂函数 `0xe0002c7c`，当前 `0xe0003320`。每次选择一路资源，读取八档配置：

```c
for (i = 0; i < 8; ++i) {
    full[i] = ((uint32_t)(base_scale * full_percent[i])) / 100;
    drop[i] = ((uint32_t)(255 * drop_percent[i])) / 100;
}
program_full_thresholds(source, full);
program_drop_thresholds(source, drop);
```

`base_scale` 来自内部状态 `+0x20a`（u16）。乘法按 RV32 低 32 位结果计算，再无符号整除，没有浮点四舍五入。函数内没有把百分比强制截断到 100：原厂满载表中的 107 有实际作用。

例如 `base_scale=512`，原厂满载百分比 `{15,30,45,60,75,95,100,107}` 换成 `{76,153,230,307,384,486,512,547}`。丢弃百分比 0/100 换成硬件输入 0/255。

112 组解释测试覆盖四个资源、0/1/64/512/4096/16384/65535 基准及随机表值。捕获传给硬件 setter 的八项数组，与独立整数模型一致。setter 实际寄存器语义与随机丢弃执行流程仍需继续核对；四路资源不能未经核实直接命名为四个 band 或 NPU 队列。

## 5. 已还原：WM VOW 八档量子分派

原厂处理函数候选入口 `0xe00cd73a`，当前 `0xe00d388e`；入口/返回的压缩扩展尚未全部解码，因此不声称完整函数已仿真。

可以从已解码的内部控制流确认：

- ctrl `0x20..0x27`：把请求值交给 ROM API 表 `0x81b8b0` 中的函数，索引为 `ctrl-0x20`。
- ctrl `0x28`：循环 0..7，逐个读取请求 `+0x10+i` 的字节，调用同一个量子 setter。
- 查询通过相邻 API 表 `0x81b8b4` 逐档读回，读到零会标记失败。
- 当前 WM 在单档及全部档位写入前增加了零值检查。全部档位路径遇零会记失败并继续处理其他档位，不能假定为原子事务。
- B27 补丁153量子表 `{6,12,16,20,24,28,32,36}` 全部非零，与该命令处理要求兼容。这只是验证命令解析，量子单位及完整硬件 DRR 行为仍依赖 HAL 和硬件证据。

## 6. 当前 WA 新增入口

当前版本在命令分派中有 `acm drop cp patch enable = %d, %d`。在 `0x10018588/0x1001858c` 解析出的调用目标为 `0xe0003f66`。

此小函数实际根据第一个参数的 bit0，把 ACM 状态 `+0x221` 写为 0 或 1；该小函数本身未读取第二个参数。不能从日志名称扩展为“TCP ACK 优先修复”或“Wi-Fi 消失修复”。已继续定位到两个消费点：

- `0x10002396`：标志非零时，跳过把一段更新缓冲区复制到旧目的区的调用；这不是直接证明数据包丢弃。
- `0x10002478`：标志非零时转入 `0x100025b6` 的另一套逐 STA 同步流程。它按 `STA索引×3` 取旧状态 `+0x48e` 与输入状态 `+0x282`，比较两者低 4 位；变化时更新 STA 记录 `+0x4a` 的相关标志、设置更新 bitmap，并复制对应的 3 字节状态。未变化时清相应 bitmap 位。

原厂旧 WA 的对应同步路径主要按 rate-shift 与 RED 位更新记录；当前新增路径不宜直接称为“原厂完整算法”。当前 WA 的运行启用状态字节也由旧版 `+0x222` 移到了 `+0x223`，所以配置解析布局相同不代表全部内部结构相同。

完整数据包处理及这个开关的默认值仍需核对；本轮没有向实机发送命令启用它。

